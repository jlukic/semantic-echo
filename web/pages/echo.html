A public WebTransport echo. Point a client at it and your datagrams and streams come straight back.

const wt = new WebTransport('https://echo.semantic-ui.com/echo');
await wt.ready;

const writer = wt.datagrams.writable.getWriter();
await writer.write(new TextEncoder().encode('hello'));

const reader = wt.datagrams.readable.getReader();
const { value } = await reader.read();  // "hello"

On Safari those two streams are createWritable() and createReadable() factories instead. Other differences worth knowing.

What the server saw

A failed WebTransport handshake reaches your code as one WebTransportError with an empty message. That is the whole diagnostic the browser offers, on every engine, for every cause. The server on the other end saw considerably more.

Connect above, then this fills in with what arrived here from your address.

Endpoints

Every endpoint runs the same echo handler behind the same certificate. They differ in what they advertise during the handshake, which is the part clients disagree about.

Echo is budgeted: 1 MiB and 120 seconds per session, four sessions per address. Far above any interop or development test.
